# 한글스크립트의 큰 그림

한글 문장으로 프로그램의 의도를 분명히 쓰고, JavaScript 생태계에서 실행하는 언어를 만듭니다. 현재의 중심은 **문장형 소스 → 타입 검사 → JavaScript + 타입 선언**입니다. 이 문서는 완료 보고가 아니라 현재 지원 범위와 이후 개발의 기준입니다. 기능 추가만으로 1.0을 선언하지 않습니다.

## 순서대로 만들기

### 1. 지금 있는 언어를 믿고 사용할 수 있게

함수마다 입력·반환·원본 변경·실패 조건을 일관되게 문서화하고 예제를 실행해 검사합니다. 잘못된 입력과 오류 위치를 회귀 테스트로 남깁니다. 문장형의 모든 조합을 지원한다고 가정하지 않고 지원·부분 지원·미구현을 공개합니다. 현재 0.8 작업은 문서·자료구조·아이콘·배포에 집중합니다.

### 2. 언어 내부를 확장하기 좋은 구조로

현재 문장·들여쓰기는 규칙 기반 파서로 처리하고 표현식에는 TypeScript AST를 활용합니다. 문장 전체를 나타내는 전용 AST와 범위 정보를 도입한 뒤 문법 검사·타입 연결·출력·포맷을 분리합니다. 이를 기반으로 오류를 여러 개 복구해서 보여주고, 정확한 소스맵과 프로젝트 단위 증분 분석을 만듭니다.

### 3. 실용적인 개발 환경을 완성하기

편집기의 전체 속성 자동 완성·자동 import·참조와 이름 변경을 LSP에 연결합니다. 프로젝트 설정·증분 빌드·테스트 명령을 제공하고 React/Vue에서 안정적으로 쓰는 예제를 유지합니다. 파일·네트워크·날짜·객체 등은 Node와 브라우저의 권한 차이를 구분한 선택 모듈로 설계합니다.

### 4. 문장이 탄탄할수록 검사할 수 있는 내용 늘리기

이름과 타입은 등장인물과 사물을, 사전·사후 조건은 세계의 규칙을, 함수와 모듈은 사건과 장면을 표현합니다. 현재는 `확인한다`로 실행 중 조건을 검사할 수 있습니다. 다음으로 입력 조건·결과 조건·예제 테스트를 더 읽기 쉬운 문장으로 선언하는 방식을 설계할 수 있습니다. 효과가 있는 문법인지 작은 실험과 실제 예제로 먼저 검증합니다.

### 5. 1.0을 위한 기준 정하기

문법 명세와 표준 API를 고정하고 호환성·폐기 정책을 확정합니다. 핵심 오류 사례, 적합성 테스트, 편집기 기능, 선언 출력, Node·브라우저·프레임워크 연동을 릴리스 기준으로 정합니다. 성능은 환경과 입력 크기를 함께 공개하고 회귀를 추적합니다. 완료되지 않은 항목이 있으면 이름을 붙여 공개합니다.

## AI와 별도 실행 엔진의 위치

핵심 문법·타입·컴파일·조건 검사에는 AI API가 필요하지 않습니다. 자유로운 산문에서 의도를 추출하는 기능은 선택적인 작성 보조로 실험할 수 있고 로컬 모델도 가능합니다. 생성한 결과도 같은 검사·테스트를 통과해야 합니다. 현재 자유 산문 실행, AI 기반 문장 해석, 자동 정형 증명은 제공하지 않습니다.

JS + .d.ts 경로는 기존 생태계와 타입을 재사용하는 현재의 실행 계약입니다. 독립 VM·바이트코드·네이티브 출력은 별도의 큰 프로젝트이므로 실제 요구와 측정 결과가 생기면 검토합니다. 정식 문서와 지원 도구를 갖추는 데 독립 실행 엔진이 필수인 것은 아닙니다.
