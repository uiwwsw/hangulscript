# 오류 읽고 고치기

문법·타입 오류는 원본 `.hgs`의 파일 이름·행·열로 표시됩니다. VS Code에서는 Problems 패널과 밑줄, Vite에서는 개발 화면의 오류와 실패한 빌드, CLI에서는 실패 종료 코드로 확인합니다. 웹 데모의 오류 항목을 누르면 해당 위치로 이동합니다.

```text
main.hgs:1:1 [TS2322] 선언한 타입과 대입한 값의 타입을 확인하세요.
```

`값: 숫자는 "문자"이다`는 숫자 타입과 문자열 값이 달라 실패합니다. `값: 숫자는 42이다`처럼 고치세요.

| 표시 | 뜻 | 확인할 내용 |
| --- | --- | --- |
| HGS1001 | 문장 또는 들여쓰기 오류 | 콜론·블록·지원 문법 |
| TS2304 | 찾을 수 없는 이름 | 오타·선언·스코프 |
| TS2307 | 찾을 수 없는 모듈 | 상대 경로·실제 파일·타입 선언 |
| TS2322 | 대입 타입 불일치 | 변수 타입과 넣는 값 |
| TS2339 | 없는 속성·메서드 | 대상 타입과 속성 이름 |
| TS2345 | 인자 타입 불일치 | 함수에 넘긴 값의 타입 |
| TS2554 | 인자 개수 불일치 | 필수 인자의 개수 |
| TS7006 | 명시되지 않은 매개변수 타입 | 숫자·문자열 등 타입 |

`any` 또는 `아무거나`는 타입 검사를 느슨하게 만듭니다. 빈 목록 `[]`의 기본 타입도 현재 `any[]`이므로 엄격히 검사하려면 `점수들: 목록<숫자>는 []이다`처럼 적으세요. 타입이 맞아도 0으로 나누기·잘못된 범위·사용자 규칙 위반은 별도의 실행 검사가 필요합니다.

문자열 길이와 진단 열은 JavaScript UTF-16 기준입니다. `목록으로("문자열")`의 문자열 순회는 코드 포인트 기준입니다. 이모지나 결합 문자의 사용자 인식 글자 수와는 다를 수 있습니다.
