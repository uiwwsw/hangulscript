# 뜻이 분명한 문장으로 개발하기

잘 쓴 코드에는 좋은 글과 닮은 점이 있습니다. 대상의 이름이 분명하고, 행동의 이유가 있으며, 앞에서 정한 규칙이 뒤에서도 지켜집니다. 한글스크립트에서는 이를 이름·타입·조건·결과·모듈로 표현합니다.

- 인물과 사물: 자료의 이름과 타입을 정합니다.
- 세계의 규칙: 허용하는 값과 불변 조건을 분명히 씁니다.
- 사건: 함수가 무엇을 받아 무엇을 돌려주는지 정합니다.
- 장면: 관련 있는 함수를 모듈로 묶습니다.
- 앞뒤의 일관성: 타입 검사와 테스트로 확인합니다.

```hgs
할인후금액(가격: 숫자, 할인율: 숫자)를 정의한다:
    확인한다(Number.isFinite(가격) && 가격 >= 0, "가격은 유한한 0 이상의 수입니다")
    확인한다(Number.isFinite(할인율) && 할인율 >= 0 && 할인율 <= 100, "할인율은 0~100입니다")
    결과는 가격 - 반올림(가격 * 할인율 / 100)이다
    확인한다(결과 >= 0, "결제 금액은 음수가 아닙니다")
    돌려주기 결과

확인한다(할인후금액(10000, 20) === 8000, "20% 할인 계산을 확인합니다")
출력(할인후금액(10000, 20))
```

이 예제는 입력 조건·처리·결과 조건을 코드에 남깁니다. 타입 검사는 숫자 자리에 문자열을 전달하는 오류를 찾고, `확인한다`는 실행 중 조건 위반을 찾습니다. 모든 경우의 올바름을 수학적으로 증명하는 기능은 아닙니다.

## AI API가 꼭 필요한가요?

필요하지 않습니다. 정해진 문법, 타입, 조건 검사, 명시적인 예외, 실행 가능한 예제만으로도 문장이 명확할수록 검사 가능한 내용을 늘릴 수 있습니다. 현재 언어는 소설이나 임의의 산문을 자동으로 실행하지 않습니다.

자유로운 글에서 프로그램 후보를 제안하는 보조 기능은 향후 AI로 만들 수 있습니다. 로컬 모델도 가능하며 외부 API만이 방법은 아닙니다. 다만 생성된 코드에는 같은 컴파일·타입·테스트 검증이 필요합니다. 핵심 문법과 실행은 AI 서비스 없이 동작합니다.
